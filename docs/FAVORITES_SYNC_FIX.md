# Исправление: Синхронизация избранного между экранами

## Проблема

Изменения в избранном не синхронизировались между экранами в реальном времени:
- Добавление/удаление в ленте → не отображалось в профиле
- Удаление из профиля → не отображалось в ленте
- Изменения были видны только после перезагрузки приложения

## Причина

Каждый экран использовал локальное состояние:
- `FeedScreen`: использовал `favoriteLookIds` из `lookStore`
- `ProfileScreen`: использовал локальный `favoriteLooks` state

При переключении между экранами данные не обновлялись автоматически.

## Решение

Использован `useFocusEffect` из React Navigation для автоматического обновления данных при фокусе на экране.

### Изменения в ProfileScreen.tsx

```typescript
// 1. Добавлен import
import { useFocusEffect } from '@react-navigation/native';
import { useCallback } from 'react';

// 2. Функции загрузки обернуты в useCallback
const loadStylistLooks = useCallback(async () => {
  // ... загрузка образов стилиста
}, [user, fetchStylistByUserId, fetchStylistLooks]);

const loadFavoriteLooks = useCallback(async () => {
  // ... загрузка избранного клиента
}, [user]);

// 3. Добавлен useFocusEffect
useFocusEffect(
  useCallback(() => {
    if (user) {
      if (isStylist) {
        loadStylistLooks();  // Обновляем образы стилиста
      } else {
        loadFavoriteLooks(); // Обновляем избранное клиента
      }
    }
  }, [user, isStylist, loadStylistLooks, loadFavoriteLooks])
);
```

### Изменения в FeedScreen.tsx

```typescript
// 1. Добавлен import
import { useFocusEffect } from '@react-navigation/native';
import { useCallback } from 'react';

// 2. Добавлен useFocusEffect
useFocusEffect(
  useCallback(() => {
    if (user) {
      fetchFavorites(user.id); // Обновляем избранное при фокусе
    }
  }, [user])
);
```

## Как это работает

### useFocusEffect
- Вызывается каждый раз, когда экран получает фокус
- Автоматически очищается при потере фокуса
- Похож на `useEffect`, но срабатывает при навигации

### useCallback
- Мемоизирует функции
- Предотвращает бесконечные циклы обновлений
- Стабилизирует зависимости для `useFocusEffect`

## Сценарии работы

### Сценарий 1: Добавление в избранное из ленты
1. Пользователь в **Ленте**
2. Нажимает ❤️ на образе
3. Переходит в **Профиль**
4. ✅ `useFocusEffect` автоматически загружает избранное
5. Образ появляется в секции "Избранное"

### Сценарий 2: Удаление из профиля
1. Пользователь в **Профиле**
2. Удаляет образ из избранного (✕)
3. ✅ Список обновляется сразу (через `loadFavoriteLooks`)
4. Переходит в **Ленту**
5. ✅ `useFocusEffect` обновляет состояние сердечек
6. Сердечко становится серым

### Сценарий 3: Стилист добавляет образ
1. Стилист в **Профиле**
2. Добавляет новый образ
3. ✅ Список обновляется сразу (через `loadStylistLooks`)
4. Переходит в **Ленту**
5. ✅ Образ отображается в общей ленте

## Производительность

### Оптимизация
- ✅ `useCallback` предотвращает лишние рендеры
- ✅ Данные загружаются только при фокусе
- ✅ Нет постоянного polling

### Нагрузка на БД
- Запрос выполняется при каждом переключении на экран
- Для избранного: 2 запроса (favorite_looks + stylist_looks)
- Для образов стилиста: 1 запрос

**Среднее использование:**
- Клиент: 2-4 запроса в минуту (при активном переключении)
- Стилист: 1-2 запроса в минуту

### Почему выбран useFocusEffect

✅ **Простота** - нативное решение React Navigation  
✅ **Надежность** - проверенный паттерн

## Отладка

### Если синхронизация не работает

1. **Проверить консоль:**
```javascript
console.log('ProfileScreen focused');
console.log('Favorites loaded:', favoriteLooks.length);
```

2. **Проверить навигацию:**
- useFocusEffect срабатывает только при навигации через React Navigation
- Не срабатывает при перезагрузке приложения

3. **Проверить user:**
- Убедитесь, что `user` не null
- Проверьте роль: `user?.user_metadata?.role`

### Логирование

Добавьте для отладки:
```typescript
useFocusEffect(
  useCallback(() => {
    console.log('Screen focused, user:', user?.id, 'isStylist:', isStylist);
    // ... загрузка данных
  }, [user, isStylist, ...])
);
```
