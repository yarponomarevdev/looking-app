# Обновление: Deep Links через /feed

## 🎯 Что изменилось

Ссылки для шеринга образов теперь идут через `/feed` для правильной работы с неавторизованными пользователями.

## ✅ Новый формат ссылок

### Было (не работало для неавторизованных):
```
https://looking-web.vercel.app?stylist=xxx&look=yyy
```

### Стало (работает для всех):
```
https://looking-web.vercel.app/feed?stylist=xxx&look=yyy
```

## 📋 Измененные файлы

### 1. `src/screens/FeedScreen.tsx`
- ✅ Добавлена обработка параметров `route.params.stylist` и `route.params.look`
- ✅ Автоматический переход к профилю стилиста при наличии параметров
- ✅ Ссылки генерируются с `/feed`

### 2. `src/navigation/AppNavigator.tsx`
- ✅ Конфигурация Feed теперь принимает параметры `stylist` и `look`
- ✅ Улучшенная обработка в `getStateFromPath`:
  - Проверяет наличие `/feed` в пути
  - Для `/feed` открывает сначала Main → Feed, затем переходит к стилисту
  - Для старого формата (без `/feed`) работает как раньше

### 3. Документация
- ✅ `ПРАВИЛЬНЫЙ_URL.md` - обновлены примеры
- ✅ `docs/DEEP_LINKS_TROUBLESHOOTING.md` - обновлены инструкции

## 🔄 Как это работает

### Для неавторизованных пользователей:

1. Пользователь открывает: `https://looking-web.vercel.app/feed?stylist=xxx&look=yyy`
2. Загружается приложение
3. Открывается экран Feed
4. Feed получает параметры `stylist` и `look`
5. После загрузки данных автоматически переходит к профилю стилиста
6. Открывается профиль стилиста с выбранным образом
7. При попытке записаться - предлагается войти

### Для авторизованных пользователей:

1-6. То же самое
7. Открывается модальное окно бронирования с выбранным образом

1. **Откройте в режиме инкогнито (неавторизованный):**
   ```
   https://looking-web.vercel.app/feed?stylist=1a89bf8c-bb99-4a9b-8c9d-0d7435a8c1e6&look=4ceec4e3-dfc2-49b9-a5bd-eac0beffd102
   ```

2. **Ожидаемое поведение:**
   - ✅ Приложение открывается
   - ✅ Показывается Feed
   - ✅ Автоматический переход к профилю стилиста
   - ✅ Видно выбранный образ
   - ✅ Кнопка "Записаться" доступна

### Проверка для авторизованных:

1. **Войдите в приложение**
2. **Откройте ту же ссылку**
3. **Ожидаемое поведение:**
   - ✅ Все то же самое
   - ✅ Модальное окно бронирования открывается автоматически

## ⚡ Производительность

- Задержка 300ms перед переходом к стилисту, чтобы Feed успел отобразиться
- Переход происходит только после загрузки списка образов
- Очистка таймера при unmount компонента

## 🐛 Известные особенности

1. **Небольшая задержка:** Пользователь может кратковременно увидеть Feed перед переходом к стилисту - это нормально и нужно для инициализации
2. **Требуется /feed:** Старый формат без `/feed` будет пытаться открыть стилиста напрямую, что может не работать для неавторизованных
