# Упрощение статусов стилистов

## Изменения

Статусы стилистов упрощены с **трех** до **двух** для более понятного UX.

### Старые статусы (3 варианта)
- ✅ Свободен (available)
- ⏳ Занят (busy)
- ⛔ Офлайн (offline)

### Новые статусы (2 варианта)
- ✅ **Активен** (active) - стилист доступен для новых записей
- ⛔ **Не активен** (inactive) - стилист не принимает записи

## Обоснование изменения

1. **Упрощение для пользователей**: Клиентам проще понять два состояния вместо трех
2. **Упрощение для стилистов**: Быстрое переключение между "работаю" и "не работаю"
3. **Логичность**: Состояние "Занят" по сути означало то же, что и "Свободен" (оба отображались на карте)

## Что было изменено

### 1. TypeScript типы (`src/types/index.ts`)
```typescript
// Было:
status: 'available' | 'busy' | 'offline';

// Стало:
status: 'active' | 'inactive';
```

### 2. UI компоненты
Обновлены экраны и компоненты:
- ✅ `EditStylistProfileScreen.tsx` - две кнопки вместо трех
- ✅ `StylistBottomSheet.tsx` - отображение статуса
- ✅ `MallStylistsBottomSheet.tsx` - отображение статуса в списках
- ✅ `StylistDetailScreen.tsx` - отображение на странице профиля
- ✅ `StylistListScreen.tsx` - отображение в общем списке

### 3. Store (`src/store/stylistStore.ts`)
- Обновлены типы методов
- `fetchStylists()` теперь фильтрует только по `status = 'active'`
- `updateStatus()` принимает только `'active'` или `'inactive'`

### 4. База данных
- Обновлен constraint в таблице `stylists`
- Значение по умолчанию: `'active'`
- Обновлен триггер создания нового стилиста

## Миграция существующих данных

### Для новых проектов
Просто выполните обновленный файл `supabase-migration.sql`

### Для существующих проектов (с данными)

**ВАЖНО**: Если у вас уже есть стилисты в базе данных, выполните миграцию:

1. Откройте Supabase Dashboard
2. Перейдите в **SQL Editor**
3. Выполните скрипт из файла `docs/STATUS_MIGRATION.sql`

Скрипт автоматически:
- Удалит старое ограничение CHECK
- Обновит существующие данные:
  - `available` → `active`
  - `busy` → `active`
  - `offline` → `inactive`
- Добавит новое ограничение CHECK
- Установит новое значение по умолчанию

## Обратная совместимость

**Внимание**: Это breaking change!

После применения миграции:
- Старые значения статусов будут автоматически преобразованы
- Приложение должно быть обновлено одновременно с базой данных
- Старые версии приложения будут работать некорректно с новой схемой

## Rollback (откат изменений)

Если нужно откатить изменения:

```sql
-- Удаляем новое ограничение
ALTER TABLE stylists DROP CONSTRAINT IF EXISTS stylists_status_check;

-- Восстанавливаем старое ограничение
ALTER TABLE stylists
ADD CONSTRAINT stylists_status_check
CHECK (status IN ('available', 'busy', 'offline'));

-- Обновляем данные обратно (по вашему выбору)
UPDATE stylists SET status = 'available' WHERE status = 'active';
UPDATE stylists SET status = 'offline' WHERE status = 'inactive';
```

## Заключение

Изменение делает интерфейс более понятным и простым как для стилистов, так и для клиентов. Управление статусом стало проще - всего один переключатель вместо трех кнопок.
